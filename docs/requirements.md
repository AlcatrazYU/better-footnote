# Better Footnote 需求文档

## 背景

在使用 Obsidian 写论文时，核心插件 Footnotes view 可以把当前文章的脚注集中显示在右侧边栏。这个视图适合浏览脚注，但在高频写作场景下，脚注内容的直接编辑、复制、粘贴和上下文联动不够稳定，容易打断论文写作节奏。

本项目目标是制作一个新的 Obsidian 社区插件，用一个更适合论文写作的脚注侧栏替代核心脚注视图，而不是修改 Obsidian 核心插件本身。

## 用户痛点

1. 侧栏脚注编辑不顺手
   - 在核心脚注视图中，选中某条脚注后直接输入或粘贴时，光标位置不可靠。
   - 经常需要先插入空格再删除，才能把编辑焦点“激活”到目标文本内。
   - 复制脚注中的一句话时，容易复制整个脚注条目。

2. 切换上下文后位置丢失
   - 编辑第 10 条脚注时，切换到其他文档参考，再回到脚注视图，视图容易跳回第一条。
   - 用户需要重新滚动和查找正在编辑的脚注。

3. 正文与脚注缺少双向联动
   - 编辑某条脚注时，正文不会自动定位到对应的脚注引用处。
   - 点击正文里的脚注标记时，侧栏不能自动滚动到对应脚注。

4. 论文写作中的脚注常常很长
   - 人文学术论文脚注可能包含日文、中文、引用、解释、出处和长句。
   - 需要像编辑正文一样稳定地编辑脚注，而不是像操作列表项。

## 项目目标

构建一个独立的 Obsidian 插件：Better Footnote。

首版目标是提供一个右侧边栏视图，解析当前 Markdown 文件中的脚注定义，并把每条脚注渲染成真正可编辑的文本框。用户可以在侧栏中直接输入、粘贴、选中局部文本、复制局部文本，并把修改写回原 Markdown 文件。

## 非目标

首版不追求完全替代 Obsidian 的 Markdown 渲染器，也不修改核心 Footnotes view。

首版暂不处理以下复杂场景：

- inline footnote `^[...]` 的编辑；
- 引用定义跨越复杂 Markdown block 的无损往返；
- 多个同名脚注定义的高级冲突处理；
- Reading view 中点击渲染后脚注编号的完整事件接管；
- 自动整理脚注编号，这部分可以继续交给 Tidy Footnotes 一类插件。

## MVP 功能范围

1. 新增一个右侧边栏视图
   - 视图名称：Better Footnote
   - 命令：Open Better Footnote
   - Ribbon 图标：file-signature

2. 解析当前 Markdown 文件中的脚注定义
   - 支持标准脚注定义：`[^id]: content`
   - 支持多行脚注定义：后续行以至少两个空格或 tab 缩进
   - 显示脚注序号，原始脚注 id 只作为辅助信息保留在悬停提示中。

3. 侧栏直接编辑脚注
   - 每条脚注使用 textarea 编辑。
   - 输入后 debounce 写回原文。
   - 失焦时立即保存。
   - `Cmd/Ctrl+S` 在脚注编辑框内立即保存。

4. 保持编辑位置
   - 记住每个文件的侧栏滚动位置。
   - 记住当前聚焦的脚注 id。
   - 切换视图或刷新时尽量恢复编辑上下文。

5. 正文与侧栏基础联动
   - 正文光标位于 `[^id]` 引用上时，侧栏自动滚动到对应脚注。
   - 点击任意脚注卡片，正文自动跳到第一个引用位置，并短暂高亮正文中的脚注标记。
   - 每条脚注提供“脚注区”按钮，跳到文末脚注定义位置。

6. 多语言界面
   - 支持中文、英文、日文、韩文四套界面文案。
   - 语言优先级为 Obsidian 默认语言、系统默认语言、英文。
   - 保存状态、更新按钮、字数统计、空状态、错误提示都走统一文案表。

## 成功标准

首版完成后，用户应该能够：

- 打开一篇含脚注的论文；
- 打开 Better Footnote 侧栏；
- 在侧栏中直接粘贴或修改第 N 条脚注；
- 从脚注中只选中一句话复制，而不是复制整个条目；
- 切到别的文档后回到侧栏，仍能大致保持原来的脚注位置；
- 在正文中把光标放到某个 `[^id]` 上时，侧栏能定位到对应脚注。
- 在侧栏中点击某条脚注时，正文中的对应脚注标记能短暂高亮，便于确认位置。

## 风险与约束

1. 写回 Markdown 的安全性
   - 插件必须只替换目标脚注定义块，避免误改正文。
   - 保存前应重新解析当前文件，避免使用过期 offset。

2. 多行脚注格式
   - 首版会把多行脚注规范化为后续行两个空格缩进。
   - 复杂缩进可能被轻微格式化，这是可接受的 MVP 约束。

3. Obsidian 模式差异
   - Source mode、Live Preview、Reading view 的 DOM 和编辑器行为不同。
   - 首版以 Markdown 编辑器中的源码级脚注引用 `[^id]` 为主要联动对象。

## 后续增强

- 支持 inline footnote 的只读展示和后续编辑。
- 增加脚注搜索、过滤和按正文顺序/定义顺序排序。
- 增加“固定当前脚注”模式，避免正文光标移动时侧栏跟随。
- 增加脚注预览渲染。
- 增加跳转到上一条/下一条脚注的快捷键。
- 增加自动检测脚注孤儿引用和未引用定义。
- 与 Tidy Footnotes 做轻量协作，而不是重复编号整理能力。
